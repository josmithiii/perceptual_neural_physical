EfficientNet-B0 is the base model of the EfficientNet family, designed using neural architecture search with a compound scaling method. Here's its architecture:

Key Characteristics
Input: 224×224×3 images (though your code modifies this via the conv2d layer before it)
Total parameters: ~5.3 million
Depth: 18 main blocks (plus stem and head)
Architecture Structure

1. Stem:
   - Conv2d 3×3, stride 2, 32 filters
   - BatchNorm + Swish activation

2. MBConv Blocks (Mobile Inverted Bottleneck Convolution):
    Stage 1: 1 block, 16 filters, 1×1 kernel, stride 1
    Stage 2: 2 blocks, 24 filters, 3×3 kernel, stride 2
    Stage 3: 2 blocks, 40 filters, 5×5 kernel, stride 2
    Stage 4: 3 blocks, 80 filters, 3×3 kernel, stride 2
    Stage 5: 3 blocks, 112 filters, 5×5 kernel, stride 1
    Stage 6: 4 blocks, 192 filters, 5×5 kernel, stride 2
    Stage 7: 1 block, 320 filters, 3×3 kernel, stride 1

3. Head:
    Conv2d 1×1, 1280 filters
    Global average pooling
    Fully connected layer → num_classes (in your case, outdim)

Key Features

    Squeeze-and-Excitation (SE): Attention mechanism in each MBConv block
    Swish activation: x * sigmoid(x) instead of ReLU
    Depthwise separable convolutions: Reduces parameters and computation
    Compound scaling: B1-B7 scale width, depth, and resolution proportionally

In your code: The num_classes=outdim replaces the final FC layer to
output your desired parameter dimensions instead of ImageNet's 1000 classes.

> Do both report parameter loss?

⏺ Yes, both optimizers report parameter loss! Here's what gets logged:

  Losses Reported During Training

  For All Optimizers (Adam, Sophia, AdamW):

  During Training:
  - train_loss - The actual training loss (depends on loss_type: "ploss", "weighted_p", etc.)
  - lr - Learning rate (tracked every epoch)

  During Validation:
  - val_loss - Validation loss (same type as training loss)
  - ploss_metrics - Always computed as pure parameter MSE, regardless of loss_type! (line 318, 358)

  During Testing:
  - test_loss - Test loss
  - ploss - Pure parameter MSE on test set (line 300)
  - macro_metrics - Macro-averaged metrics
  - micro_metrics - Micro-averaged metrics
  - mss metrics - Multi-scale spectral metrics

  Key Insight

  The code is smart! Even if you train with PNP loss (weighted_p), it
  still tracks pure parameter loss (ploss_metrics) during validation
  and testing. This means:

  1. Training loss (train_loss, val_loss):
    - With loss_type="ploss" → Simple parameter MSE
    - With loss_type="weighted_p" → PNP loss (weighted by Riemannian metric M)
  2. Parameter loss (ploss_metrics, ploss):
    - Always computed as F.mse_loss(outputs, y) (lines 258, 265)
    - Gives you a fair comparison between different loss types
    - Shows actual parameter estimation accuracy

  What This Means for Your Comparison

  When comparing Adam vs Sophia, you can look at:

  In TensorBoard:
  - train_loss vs val_loss - Convergence behavior
  - ploss_metrics - Direct parameter estimation accuracy (what you care about!)
  - lr - Learning rate schedule

  After Testing:
  - ploss - Final parameter estimation error on test set
  - macro_metrics, micro_metrics - Per-parameter statistics
  - mss metrics - Spectral reconstruction quality

  Example TensorBoard View

  When you run:
  tensorboard --logdir=outputs/icassp25/f_W/

  You'll see these curves for both Adam and Sophia:
  - 📉 train_loss - Should decrease steadily
  - 📉 val_loss - Should decrease and track train_loss
  - 📊 ploss_metrics - Main metric: parameter estimation MSE
  - 📈 lr - Learning rate (will show ReduceLROnPlateau adjustments)

  So yes, both optimizers report identical metrics, making them
  directly comparable! The ploss_metrics on the validation set is your
  key metric for determining which optimizer gives better percussion
  parameter estimation.
